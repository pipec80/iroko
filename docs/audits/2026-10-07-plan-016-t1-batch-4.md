## Decisiones y hallazgos

- **RS-01 revalidado**, receptor 014-T1, sin crear un duplicado: `robot: false`
  oculta navegación; página y acciones no verifican disponibilidad ni rol.
  Storage, tablas y RPC autorizan cualquier miembro. Un `viewer` conserva
  capacidad de escritura. El RPC sí comprueba identidad y membresía viva;
  no se demuestra acceso entre cuentas ni acceso anónimo.
- **N-11, P2 estático:** cliente y acción aceptan hasta 5 MiB; `next.config.ts`
  limita Server Actions a `2mb`. Un archivo admitido por UI puede exceder
  transporte antes de la acción. `handleUpload` no captura ese rechazo.
  Aceptación futura: verificar fronteras multipart y mensaje controlado.
- **N-12, P2 estático:** seleccionar A válido y después B inválido conserva
  A en estado; el botón puede subir A tras mostrar el error de B.
  Aceptación futura: verificar estado, nombre visible y archivo enviado.
- **D-05, P2 de pruebas:** `05_grants.test.sql` consulta
  `information_schema.role_usage_grants` para afirmar ausencia de USAGE de
  esquemas. La vista no representa permisos de esquemas y omite PUBLIC;
  los tres asserts no detectan ese grant. No prueba exposición actual.
  Contraste: [PostgreSQL 17, role_usage_grants](https://www.postgresql.org/docs/17/infoschema-role-usage-grants.html).
  Aceptación futura: `has_schema_privilege` para roles efectivos y caso
  negativo que introduzca USAGE temporalmente en una base desechable.
- **Candidato D-06, pendiente de contraste:** el reemplazo transaccional
  no bloquea una fila estable de cuenta. Dos sesiones sobre un tenant vacío
  pueden borrar cero filas e insertar conjuntos distintos. Atomicidad frente
  a fallo no implica exclusión entre reemplazos. Runtime `[NO VERIFICADO]`.
- Pruning de originales y subidas fallidas requieren ampliar análisis de
  intercalaciones; no se registra aún un hallazgo confirmado independiente.
